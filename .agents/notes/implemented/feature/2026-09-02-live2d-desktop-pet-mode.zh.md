# Agent Note: Live2D 桌宠模式

Status: implemented

[English](2026-09-02-live2d-desktop-pet-mode.md) | 中文

## Problem

Live2D 陪伴模型渲染在 Web 工作区右侧栏。桌面壳用户需要把模型保持为悬浮桌宠，同时不能打断主工作区，也不能增加独立的原生模型运行时。

## Decision

Qt 壳拦截 Live2D 组件发出的 `dsh://desktop-pet/toggle` 导航请求。进入模式后，创建第二个 WebEngine 视图并放入无边框、置顶的 360x480 工具窗口，移动到主屏幕右下角；主工作区窗口及其原有视图保持显示且不变。所选模型文件会缓存到同源 IndexedDB，并在桌宠页面打开后通过同源 `BroadcastChannel` 再发送一次；即使 Qt WebEngine 配置拒绝 IndexedDB 写入，桌宠模式仍可工作。Web 文档通过 `dshDesktopPet=1` 查询参数，外壳会在应用挂载后移除该页面中所有非陪伴 DOM 节点，并设置透明页面/窗口背景。桌宠显示时，外壳每 16 毫秒轮询一次桌面鼠标位置，把变化后的位置映射为 WebEngine 客户区坐标且不限制在窗口范围内，再在页面主 JavaScript world 中发送 `mousemove` 事件，使现有 `l2d` 渲染器能追踪窗口外的鼠标。Linux Wayland 会话提供 XWayland display 时，外壳会在创建应用前选择 Qt 的 `xcb` 后端；显式设置的 `QT_QPA_PLATFORM` 优先，而原生 Wayland 只提供获焦 surface 的坐标，因此会关闭全局轮询。拖动窗口可移动桌宠。垂直滚轮输入以 24x32 为步长调整窗口大小，同时保持底部中心位置不变，最小尺寸为 240x320。双击退出模式。普通工作区渲染器不会切换到桌宠显示方式。

桌面入口通过 `DeepSeekHarnessQt` user-agent 标记识别。普通浏览器仍保持右侧栏行为，不显示原生窗口操作。

Qt 壳会在启动子进程前探测 3080 端口。若已有 Harness 服务正在监听，外壳会直接复用该服务，不声明所有权，也不会在关闭时终止它；这样再次启动不会把正常页面变成 `EADDRINUSE` 重试循环。

## Alternatives considered

**把工作区的 WebEngine 视图移入桌宠窗口。** 不采用，因为开启桌宠模式后，主窗口会失去正在使用的工作区。

**只实现浏览器 fixed-position 覆盖层。** 不采用，因为浏览器标签页不能置于其他桌面应用之上，也不能提供透明窗口外观。

**增加独立的原生 Live2D 渲染器。** 不采用，因为这会重复已有浏览器插件提供的 Cubism 运行时、模型加载和许可证范围。

**安装平台专用的全局鼠标钩子。** 不采用，因为 Qt 可以只在桌宠显示时采样桌面鼠标，并把普通客户区坐标交给现有渲染器，不需要增加操作系统钩子权限或维护多套实现。Linux 通过 XWayland 获得这条现有路径，不需要直接读取输入设备。

**通过不可见窗框边缘缩放。** 不采用，因为这会把紧凑窗口划分为移动区和缩放命中区；滚轮缩放可让整个窗口表面继续用于移动桌宠。

## Consequences

使用能提供全局坐标窗口系统的 Qt 桌面用户会获得可移动、可调整大小的置顶桌宠，模型视线可在桌面范围内追踪鼠标，同时普通工作区保持不变。滚轮缩放会保持 3:4 尺寸比例和底部中心位置，并占用桌宠上的垂直滚轮输入。鼠标轮询只在桌宠显示时运行，且只有映射后的位置变化时才向 WebEngine 发送事件。选择 `xcb` 会以原生 Wayland 集成为代价，换取桌面全局鼠标追踪和可靠的显式窗口位置；部署方可以通过 `QT_QPA_PLATFORM` 恢复原生 Wayland，但只能追踪获焦 surface 上的鼠标。桌宠模式刻意限定在桌面壳能力内，浏览器和远程页面不能请求原生窗口变化或获得全局鼠标坐标。紧凑显示会隐藏常规控件，因此使用双击退出模式。
