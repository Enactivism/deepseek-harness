# Agent Note: Live2D Galgame 模式

Status: implemented

[English](2026-09-23-live2d-galgame-mode.md) | 中文

## Problem

桌宠聊天支持开放式消息，而互动剧情需要助手提供三个玩家回复，让用户点选后直接发送。

## Decision

原生桌宠窗口将聊天和 Galgame 按钮所在区域（包括双击）交给网页处理，模型区域仍保留原生手势。

悬浮桌宠可以打开 Galgame 模式选择器，聊天窗口标题栏可以返回普通桌宠聊天。自由模式使用现有聊天输入框。剧情模式提供可选剧本卡，可设置剧情类型、角色、玩家身份和开场场景；空白文本会被省略，剧本卡会与首次剧情指令一起记录，玩家主动应用修改时会新增一条指令并从当前情节继续。剧情指令要求助手先返回剧情文本，再在 `<galgame-choices>` 中按顺序提供恰好三条编号玩家消息。浏览器只会为完整的 `1.`–`3.` 选项块渲染按钮；玩家点击后，界面会将选项原文通过同一个 Session 提交。“沉浸”视图用影院黑边只显示最新一条可见对话；切回“回看”会恢复完整记录，不改变 Session 历史，也不会请求模型。模式指令和剧本卡会以功能专用前缀写入 Session，但不会作为玩家发言显示在紧凑对话界面里。剧情指令生效期间，切换到自由模式或退出 Galgame 时会提交停止剧情输出格式的本地化指令。选项块缺失或格式错误时不会显示可选消息，并会提供重试操作。Galgame 自由和剧情模式共用一个 `chat-only` 纯聊天 Session，普通桌宠聊天使用另一个 Session；无工具组成详见[纯聊天 Session 说明](2026-09-24-live2d-galgame-chat-only-session.md)。界面会把 Galgame 页面和演出偏好保存在同源 localStorage 中，使悬浮桌宠能直接打开对应的原生聊天页面；这些偏好属于展示状态，不写入 Session 日志。

## Alternatives considered

**为剧情模式单独创建 Session。** 不采用，因为自由聊天和剧情模式属于同一段 Galgame 对话，应共用历史和模型选择。

**从无标记的编号文本中解析选项。** 不采用，因为普通剧情文本也可能包含编号列表；显式的 `<galgame-choices>` 块可以区分可发送的玩家消息。

**通过第二次模型请求或后端接口生成选项。** 不采用，因为助手可以通过现有 Session prompt 路径在一条回复中返回剧情和选项。

## Consequences

剧情指令、可选剧本卡、模式切换和玩家选中的回复都是已记录的用户消息；生成选项与剧情叙述共用一次助手回复的 token 计量，“沉浸”视图不消耗模型 token。Galgame 历史与普通桌宠聊天分开，不携带普通聊天的工具和动态运行上下文。未选择的选项只用于界面展示，不会进入模型历史。选项按钮依赖助手遵循约定格式；解析失败时界面仍显示剧情文本，并提供重试操作。跨窗口模式和剧本卡偏好同步依赖同源 localStorage；存储不可用时，同一页面内的 Galgame 界面仍可使用。
