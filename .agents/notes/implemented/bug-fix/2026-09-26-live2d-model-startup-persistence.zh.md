# Agent Note: 在应用启动时恢复已保存的 Live2D 模型

Status: implemented

[English](2026-09-26-live2d-model-startup-persistence.md) | 中文

## Problem

Live2D 选择器已经把所选模型字节保存到同源 IndexedDB，但只有桌宠页面会读取这条记录。因此普通应用重启后仍显示空选择器，用户必须再次选择同一个模型。Qt WebEngine 的文件夹选择器还会把名为 `.` 的目录占位项作为 `File` 返回；读取它的字节会因 `NotFoundError` 失败，使 profile 中没有保存记录。

## Decision

每个 `Live2DOverlay` 页面都会在启动时加载已保存的模型包。桌宠页面继续接受 IndexedDB 不可用时使用的 `BroadcastChannel` 传输；如果恢复正在进行时发生新的选择或传输，更新的模型优先。文件夹导入会在验证、渲染和持久化前排除 `.` 与 `..` 目录占位项。移除操作会同时删除 IndexedDB 记录和当前渲染模型。保存与删除操作会串行执行，避免快速更换或移除模型时，较早的异步写入在下一次启动时恢复过期模型。保存和删除的 Promise 在 IndexedDB 事务提交后才完成；读取、保存和移除失败会在陪伴界面显示。

仓库会忽略任意层级的 `live2d-models/`、`Live2DModels/` 和 `.live2d-models/` 专用目录，以及常见的 Live2D 模型和动画文件扩展名。浏览器 IndexedDB 仍是运行时的持久化位置；这些忽略规则只保护开发者可能放在 checkout 内的可选模型目录，不会把模型资源变成仓库数据。Qt 外壳让三个 WebEngine 页面共用一个命名 profile，并把持久化目录放在系统应用数据目录下，因此 IndexedDB 记录可以跨应用重启保留，同时不会把模型字节写入 checkout。

## Alternatives considered

**只在桌宠页面恢复。** 不采用，因为主工作区是正常入口，也必须在不重新打开文件选择器的情况下恢复同一份陪伴模型。

**只保存文件系统路径。** 不采用，因为浏览器文件句柄和路径在重启或权限变化后并不可靠；保存所选字节可以让现有浏览器端渲染器恢复模型，同时不把模型发送给 Host。

**把仓库模型目录作为数据源。** 不采用，因为用户模型资源可能很大并带有独立许可证，且不能成为被跟踪的仓库内容；IndexedDB 让运行时数据留在本地，而 `.gitignore` 保护可选的 checkout 内模型目录。

**用户移除模型后仍保留保存记录。** 不采用，因为下次启动会静默恢复用户明确清除的模型。

## Consequences

同一浏览器配置会在主工作区和桌宠视图恢复所选模型，换用其他浏览器或设备仍需重新选择。Qt 外壳把该 profile 保存到系统应用数据目录，不会写入仓库。没有保存记录的配置需要选择一次模型；先前的临时 profile 没有可迁移的磁盘记录。首次渲染可能需要等待异步 IndexedDB 读取。保存的模型包会占用浏览器配置空间并受该配置的配额限制；存储不可用时，当前页面仍可渲染新选择的模型，桌宠传输回退路径也仍然可用。

## Verification

Live2D 测试覆盖启动时恢复、移除、可见的存储失败和 Qt 目录占位项过滤。Qt WebEngine 进程选择一个包含七个文件的模型文件夹，确认全部七个文件提交到 IndexedDB 后退出；第二个进程使用同一配置成功恢复该模型。仓库忽略检查覆盖模型目录、模型数据和模型资源，同时确认不会忽略 Live2D 源码包。
