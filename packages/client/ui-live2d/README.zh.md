# @deepseek-ai/dsh-client-ui-live2d

[English](README.md) | 中文

面向 Harness 编程工作区的本地优先 Live2D 陪伴功能。本功能向布局的 `shell.right` 槽贡献一个可叠加条目，角色会嵌入聊天工作区右侧的固定栏；该栏参与正常布局，因此不会覆盖对话区或输入区。工具详情仍然使用独立的 `details` 栏。

空状态会说明使用流程，并允许用户选择一个模型文件夹。文件夹必须包含一个 `.model3.json` 或 `.model.json` 入口文件，以及它引用的 `.moc3`/`.moc`、贴图、动作、表情、物理和音频资源。浏览器会把所选文件转换为临时 object URL，并在交给 [`l2d`](https://github.com/hacxy/l2d) 前重写入口文档里的本地引用；模型字节不会发送给 Host 或模型提供方。

模型加载后，陪伴组件会显示当前模型名和文件数量，依据 Harness 当前选中会话的只读运行状态显示一个小状态指示，并提供模型大小、透明度、隐藏/恢复、更换和移除控制。槽条目销毁时渲染器也会一起释放，包括 WebGL 状态和 object URL，因此快速更换模型不会把旧模型留在内存里。

组件刻意保持浏览器端实现。Qt 仍然只是 WebEngine/进程外壳，不需要引入 Live2D SDK，也不需要维护第二条渲染路径。这样，本地模型的所有权和 UI 接缝都与其余 Web 插件体系保持在同一层。

页面运行在 Qt 壳中且模型加载完成后，会显示“桌宠模式”操作。进入后，外壳会打开第二个 WebEngine 视图并将其放入无边框、置顶的 360x480 小窗，在其中恢复当前模型并隐藏该视图的其他 Web UI。在能提供全局鼠标坐标的窗口系统中，模型会追踪桌面范围内的鼠标；拖动窗口可移动桌宠，在桌宠上向上滚动滚轮会同步放大模型和窗口，向下滚动会同步缩小二者；每个完整滚轮步长都保持模型与原生窗口的相同比例、保持底部中心锚点，窗口最小为 240x320；双击可关闭桌宠。普通浏览器不会显示此操作。

悬浮桌宠提供聊天和 Galgame 入口。聊天会打开一个带系统边框且可独立调整大小的原生窗口；透明桌宠窗口仍可单独拖动和缩放。普通桌宠聊天会恢复或创建自己的 Harness Session，按字面显示用户文本，并使用共享 Markdown 渲染器显示助手输出（包括 GFM、围栏代码和 KaTeX 公式），同时复用主界面的模型选择器，为该 Session 选择服务商/模型和推理等级。Galgame 自由模式和剧情模式共用另一个 Session；它使用 `chat-only` preset，只保留简短 persona，不注册工具，也不加载动态运行上下文。自由模式使用聊天输入框，剧情模式展示 AI 生成的三条消息供玩家选择；选择后会把选项文本提交到 Galgame Session。剧情回复使用带标签的选项块；如果助手没有按顺序返回恰好三条选项，界面会提供重试操作。普通桌宠聊天和 Galgame 的历史分别保存，不会混合；桌宠辅助浏览器运行时切换所选 Session 时，不会替换主工作区持久化的当前 Session。普通浏览器仍将紧凑聊天面板内嵌在预览页面中，供预览和测试使用。

## 开发

```sh
pnpm --filter @deepseek-ai/dsh-client-ui-live2d bundle
pnpm run test:gui
```

浏览器 bundle 会内联 `l2d`；React、槽渲染器和 UI primitives 仍然从 Harness 浏览器模块表解析。基于 Live2D Cubism 的运行时和模型资源有各自的许可义务；在分发一个接受任意用户模型的产品前，请查看 [`l2d` 的许可证与免责声明](https://github.com/hacxy/l2d#disclaimer) 以及 [Live2D SDK 许可证](https://www.live2d.com/en/sdk/license/)。

## 模型体验

### 本地陪伴状态、桌宠聊天与 Galgame

#### What the model sees

嵌入工作区的陪伴组件只响应本地模型状态和所选 Session 的运行状态。普通桌宠聊天通过自己的专用 Session 和标准 `prompt` 路径提交，保留该 Session 配置的工具。Galgame 的自由模式与剧情模式共用独立的 `chat-only` Session；其完整 persona 会抑制其他系统提示段落，且没有模型工具或动态运行上下文。两个桌宠 Session 都不会看到主工作区聊天，除非用户明确提供相关内容。自由模式提交玩家输入的文本。剧情模式先提交互动叙事指令，要求 AI 在 `<galgame-choices>` 块中提供三条编号选项；玩家点选后，界面会把选项原文作为用户消息提交。模式指令会记录在 Galgame Session 中，但不会作为玩家发言显示在紧凑对话界面里。剧情指令生效期间，切换到自由模式或退出 Galgame 时会提交停止剧情输出格式的指令。选项块缺失或格式错误时不会生成可选按钮，玩家可以在面板中重试。

#### Token effect

模型渲染和运行指示器不消耗 token。Galgame 请求不携带工具 schema 或动态运行上下文，并从独立的对话历史开始；普通桌宠聊天仍按自己的 Session 和工具配置计量 token。剧情开场、模式切换和重试指令是普通用户消息；三个选项与剧情叙述在同一条助手回复中返回，不会额外触发一次模型请求。

#### KV Cache effect

本地模型 UI 不影响 provider 缓存。普通桌宠聊天和 Galgame 分别使用自己的 provider 上下文，且都与主工作区 Session 相互独立。

## 已知限制与暂缓事项

- **当前模型只保存在此浏览器配置中** —— 模型文件通过同源 IndexedDB 缓存以供桌宠视图使用，不会同步到其他浏览器或设备。
- **一次一个文件夹** —— 选择结果包含多个模型入口文件时会被拒绝，避免用户选中包含多个模型的父目录后静默显示错误角色。
- **渲染能力跟随 `l2d`** —— 本包接受两种常见 Cubism 入口格式，但具体模型仍可能因为导出资源不完整或许可问题而加载失败。模型的分发和使用权始终由模型持有者负责。
- **聊天尚未驱动动画** —— 模型自身的待机/点击动作仍然有效；消息联动表情、语音/口型同步和模型库可以在未来的浏览器服务后面增加，不需要让模型字节经过 Host。
